Architecture · k3s-gitops-lab

k3s-gitops-lab, end to end

One protected branch drives a single-node K3s cluster on EC2. The public reaches it only over HTTPS, the admin and CI only over Tailscale; CI holds no stored keys, only short-lived OIDC tokens, and the node is rebuilt from git every week.

Delivery

One commit, two paths

  • Push: a merge touching k8s/** runs deploy-push (env production). It joins the tailnet as an ephemeral tag:ci device and applies as github:…:environment:production, bound to Role github-deployer in push only.
  • Pull: Argo CD polls main about every 3 minutes and syncs k8s/overlays/gitops with prune and selfHeal. No CI credential reaches the cluster.
  • After each image publish, the bot PR changes k8s/components/lab-api-image, the pin both overlays share, so one merge moves both namespaces.

Trust boundaries

What the edges allow

  • Internet: only 80/443 to Traefik. No public 22 or 6443.
  • CI: GitHub OIDC for AWS, Tailscale and the K3s API. No stored keys.
  • IMDS hop limit 1: only the ESO controller (hostNetwork) gets node credentials, then assumes a role that reads /grafana-cloud/* only.
  • Argo CD AppProjects platform and gitops fence the repo, namespaces and resource kinds.
  • A rebuilt node restores its identity (K3s CAs, Tailscale state, SSH host keys) from SSM, so kubeconfigs, the CI CA file and the tailnet device survive.
